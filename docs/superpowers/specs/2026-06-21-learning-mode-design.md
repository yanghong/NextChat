# AI 诊断式学习模式产品设计

## 目标

在 HongAI 的现有聊天体验中增加一个轻量但可扩展的“学习模式”。用户通过 `/学习` 或学习按钮表达粗略学习意图后，AI 不要求用户填写完整表单，而是像导师一样通过几轮问诊拆解目标、判断当前水平、推断可用学习节奏，并生成可执行的学习路线。之后 AI 持续按路线讲解、提问、纠错、复盘和推进下一步。

第一版重点是跑通学习闭环，不做独立学习平台。设计需要为后续学习板块、进度页、测验、学习档案管理预留数据结构和 UI 位置。

## 当前项目背景

项目当前以聊天会话为核心：

- `app/components/chat.tsx` 管理聊天消息渲染、输入区、输入动作、快捷键和发送逻辑。
- `app/store/chat.ts` 持久化 `ChatSession`、消息、会话配置和远端同步。
- `app/command.ts` 已有聊天命令框架，但当前命令前缀主要是 `:`/`：`，第一版学习模式需要新增 `/学习` 和 `/learn` 识别。
- `app/components/sidebar.tsx` 提供新聊天、历史会话和发现入口。
- 测试目前以 Jest 为主，已有源码约束型测试和 store 行为测试。

因此第一版应基于现有聊天会话扩展，而不是新增完整页面路由。这样风险低，也能复用当前模型、历史、同步、错误处理和消息渲染能力。

## 产品范围

### 第一版包含

- 聊天输入支持 `/学习`、`/学习 <学习意图>`、`/learn`、`/learn <goal>`。
- 聊天输入动作区增加“学习”入口，点击后开始学习模式或把输入框置为 `/学习 ` 并聚焦。
- 当前会话可进入学习模式，并显示轻量学习状态，例如标题/副标题或输入区上方的学习提示条。
- AI 通过诊断式对话生成学习目标、当前水平、学习节奏、阶段路线和下一步行动。
- 学习模式下的 AI 回复遵守“引导式学习”规则：少直接灌答案，多问问题、给练习、检查理解、做阶段复盘。
- 会话持久化学习元数据，刷新、切换会话、远端同步后仍知道该会话是学习模式。
- 支持退出学习模式，退出后会话保留历史消息，但不再注入学习导师提示词。
- 提供开发交付说明、测试用例矩阵、产品经理测试验收标准。

### 第一版不包含

- 独立学习首页、课程中心或多学习计划管理页。
- 固定表单要求用户填写当前水平、每天学习时间、截止日期。
- 自动解析 AI 回复并强制生成结构化学习计划卡片。
- 真正的学习进度统计、日历打卡、知识库、错题本。
- 多语言完整翻译清理。第一版可先补中文和英文关键文案，其他语言保留 fallback 或后续补齐。

## 核心体验

### 启动方式

用户可以通过两种方式开始：

1. 在输入框输入 `/学习 我想系统学 React`。
2. 点击输入区动作里的“学习”按钮。

如果用户只输入 `/学习` 或点击按钮但没有明确主题，AI 第一轮只询问学习方向，不生成计划。

如果用户输入了粗略主题，AI 第一轮进入问诊：确认学习目的、使用场景、已有基础、时间限制或偏好。AI 每轮最多问 1-3 个问题，避免一次性问卷。

### 诊断式对话

学习模式前几轮应按“诊断 -> 总结 -> 计划 -> 导学”的节奏推进：

1. 识别用户想学的主题和动机。
2. 通过少量问题判断当前水平和约束条件。
3. 在信息足够时，总结“学习档案”：
   - 学习目标。
   - 当前水平。
   - 可用时间或推荐节奏。
   - 主要短板。
   - 阶段路线。
   - 下一步学习任务。
4. 用户确认或修正后，进入正式导学。
5. 后续每次回复应包含当前小目标、讲解或练习、检查问题、下一步建议中的一部分，而不是普通问答式回答。

### 学习档案的产品形态

第一版不做复杂卡片。学习档案优先以 AI 消息中的结构化 Markdown 呈现，例如：

```markdown
## 学习档案
- 目标：4 周内能独立完成 React 管理后台页面
- 当前水平：会 JavaScript 基础，Hooks 只看过示例
- 建议节奏：工作日 30-45 分钟，周末 2 小时
- 路线：JS 回补 -> 组件 -> Hooks -> 数据流 -> 项目练习
- 下一步：完成 3 道 Hooks 概念诊断题
```

会话元数据只保存学习模式状态和最近一次学习摘要，避免第一版做复杂 AI 输出解析。后续可以从消息中提取结构化档案并渲染成固定侧栏。

### 退出和恢复

- 用户可以通过 `/退出学习`、`/exit-learn` 或学习状态提示条的关闭入口退出学习模式。
- 退出只关闭学习提示词注入，不删除聊天历史。
- 再次输入 `/学习` 可恢复或重新开始学习问诊。
- 如果已有学习摘要，AI 应先基于旧摘要询问“继续原计划还是重新制定目标”。

## AI 行为规则

学习模式需要注入专门的系统提示词。提示词应明确：

- 你是学习导师，不是只给答案的问答助手。
- 先诊断用户目标和水平，再制定学习路径。
- 不要求用户一次性填写表单；通过自然对话收集必要信息。
- 每轮最多问 1-3 个问题。
- 对初学者使用小步解释、例子和检查题。
- 对有基础用户优先使用任务、项目、反例和追问。
- 当信息足够时输出“学习档案”和阶段路线。
- 每个阶段都要包含可执行任务和理解检查。
- 用户答错时先指出关键误区，再给更小的提示。
- 不伪造用户水平；不确定时继续提问。

第一版不需要服务端新增模型能力，直接在 `getMessagesWithMemory()` 的系统消息拼接中按会话状态注入学习模式提示词。

## 技术设计

### 数据结构

扩展 `ChatSession`：

```ts
export type LearningModeState = {
  enabled: boolean;
  phase: "diagnosing" | "planning" | "learning" | "reviewing";
  initialIntent?: string;
  summary?: string;
  updatedAt: number;
};

export interface ChatSession {
  // existing fields
  learning?: LearningModeState;
}
```

字段说明：

- `enabled`: 当前会话是否处于学习模式。
- `phase`: 仅用于 UI 提示和后续扩展，不强依赖 AI 回复解析。
- `initialIntent`: 用户启动学习模式时输入的粗略目标。
- `summary`: 最近一次学习档案或 AI 总结，第一版可由用户或后续逻辑更新；实现时可以先保留为空。
- `updatedAt`: 用于迁移、同步和后续排序。

迁移策略：

- chat store version 从 `3.6` 升级到下一版本。
- 老会话默认 `learning` 为空或 `{ enabled: false }`。
- `normalizeSession` 保证旧数据加载不报错。
- 远端会话加载后同样 normalize。

### 命令识别

新增学习命令识别模块，避免把所有 `/` 都变成命令：

- 只识别输入开头完全匹配 `/学习`、`/study`、`/learn`。
- 命令和意图之间必须是空白边界或输入结束：`/学习 React` 生效，`/学习React` 按普通文本发送；`/learn Python` 生效，`/learnPython` 按普通文本发送。
- 支持退出命令 `/退出学习`、`/exit-learn`。
- 其他以 `/` 开头的内容仍作为普通消息发送。

建议新增文件：

- `app/utils/learning.ts`: 学习命令解析、学习系统提示词生成、学习会话状态 helper。

### Chat Store

在 `app/store/chat.ts` 增加方法：

- `startLearningMode(initialIntent?: string)`: 设置当前会话 `learning.enabled = true`，phase 设为 `diagnosing`，保存 initialIntent。
- `stopLearningMode()`: 设置当前会话 `learning.enabled = false`。
- `updateLearningMode(updater)`: 后续扩展使用。

发送逻辑：

- 用户输入 `/学习 React` 时，不把原始命令作为普通用户消息发给模型。
- 生成实际用户消息，例如“我想进入学习模式，学习目标初步是：React。请先通过诊断式问题了解我的目标和水平。”
- 用户输入 `/学习` 时，生成实际用户消息：“我想进入学习模式，请先问我想学什么。”
- 用户退出命令只更新状态并追加一条本地提示或 toast，不调用模型。
- 第一版不解析 AI 回复来自动更新 `learning.summary`。如果用户清空上下文且 summary 为空，后续学习模式提示词应要求 AI 重新做简短问诊；如果后续版本能可靠提取 summary，再用于恢复学习计划。
- `phase` 第一版只作为 UI 和后续扩展元数据，不作为控制 AI 行为的强状态机。

### Chat UI

在 `app/components/chat.tsx`：

- 输入动作区新增“学习”按钮。
- 当前会话 `learning.enabled` 时，在聊天标题副标题或输入区上方显示“学习模式中”。
- 学习状态提示条提供退出入口。
- 发送前先解析学习命令，再决定是进入学习模式、退出学习模式，还是普通发送。

设计约束：

- 不新增复杂弹窗。
- 不要求用户填写表单。
- 不影响图片上传、模型切换、Web Search、MCP、语音等现有动作。
- 移动端需要保证提示条和输入区不重叠。

### Locales

至少补充中文和英文：

- 学习按钮。
- 学习模式中。
- 退出学习。
- 学习模式已开启/已退出。
- 学习命令帮助文本。

其他语言可暂时复用英文 fallback，避免第一版引入大量翻译工作。

## 错误处理

- 没有 API Key 或模型请求失败时，沿用现有聊天错误处理；学习模式状态不应丢失。
- 用户在学习模式中切换模型，学习状态不变。
- 用户清空上下文后，学习模式状态仍保留，但 AI 应基于 learning summary 或重新问诊。
- 学习命令解析失败时，不吞消息，按普通聊天发送。
- 远端同步缺少 `learning` 字段时不报错。

## 测试用例设计

### 自动化测试

开发工程师应先写失败测试，再实现。

1. 学习命令解析：
   - `/学习` 返回 start 命令，意图为空。
   - `/学习 React Hooks` 返回 start 命令，意图为 `React Hooks`。
   - `/learn Python` 返回 start 命令。
   - `/退出学习` 返回 stop 命令。
   - `/not-a-learning-command` 返回普通输入。

2. Chat store：
   - `startLearningMode()` 会设置 `learning.enabled = true`、`phase = diagnosing`、保存 initialIntent。
   - `stopLearningMode()` 只关闭 enabled，不删除消息。
   - 旧会话 migrate/rehydrate 后没有 learning 字段也能正常使用。
   - 远端加载旧会话后 learning 字段被安全 normalize。

3. 系统提示词：
   - 学习模式开启时，`getMessagesWithMemory()` 包含学习导师系统提示词。
   - 学习模式关闭时，不包含学习导师提示词。
   - 学习提示词不会覆盖已有 MCP/system prompt，而是追加。

4. Chat UI 源码/组件行为：
   - 输入动作区包含学习入口。
   - 学习模式开启时显示“学习模式中”状态。
   - 退出学习入口调用 stop 方法。
   - `/学习 React` 不作为原始命令文本直接发送。

5. 回归：
   - 普通聊天发送不受影响。
   - 图片模式、模型切换、Web Search、MCP action 入口仍存在。
   - 旧测试继续通过。

### 测试工程师手工用例

测试前测试工程师需要先写完整测试用例，产品经理按本节检查覆盖。

| 场景 | 步骤 | 预期 |
| --- | --- | --- |
| 启动空学习模式 | 输入 `/学习` 并发送 | 会话进入学习模式，AI 先问想学什么 |
| 启动带主题学习模式 | 输入 `/学习 我想学 React` | AI 不直接给完整课程表，先问目标和基础 |
| 多轮问诊 | 回答 AI 的 2-3 轮问题 | AI 总结目标、水平、节奏、路线和下一步 |
| 导学推进 | 按 AI 要求回答练习 | AI 纠错或推进下一步，而不是变成普通聊天 |
| 退出学习模式 | 输入 `/退出学习` 或点击退出 | 状态关闭，后续回复不再注入学习导师提示词 |
| 恢复旧学习会话 | 切换会话再回来，或刷新页面 | 学习模式状态仍保留 |
| 普通 slash 文本 | 输入 `/help` 或其他 slash 文本 | 不误触发学习模式 |
| 模型切换 | 学习模式中切换模型 | 学习状态不丢失 |
| 无 API Key | 学习模式中发送消息但未绑定 key | 仍展示现有 API Key 引导，不丢学习状态 |
| 移动端 | 小屏打开学习模式 | 状态条、输入框、发送按钮不重叠 |

### 产品经理测试校验标准

产品经理验收测试用例时，需要确认：

- 覆盖启动、问诊、计划生成、导学、复盘、退出、恢复完整闭环。
- 覆盖正常路径、异常路径、旧数据兼容和移动端显示。
- 覆盖“AI 生成目标/水平/节奏”这一核心需求，而不是回退成用户填表。
- 覆盖不影响普通聊天和现有输入动作。

产品经理最终用户级测试通过标准：

- 用户只输入一个模糊学习意图，也能被 AI 引导到清晰学习目标。
- AI 能通过提问而不是表单收集当前水平和时间约束。
- AI 生成的学习路线可执行，并能继续带用户学习下一步。
- 用户能清楚知道当前会话处于学习模式，并能退出。
- 功能不破坏原有聊天主流程。

## 交付流程

1. 产品经理确认本设计。
2. 开发工程师按实现计划 TDD 开发。
3. 测试工程师先基于本设计写完整测试用例。
4. 产品经理审查测试用例覆盖性，不完整则退回补充。
5. 测试工程师执行自动化和手工测试。
6. 测试通过后，产品经理再做一轮用户级验收。
7. 验收通过后再进入发布或 PR 流程。
